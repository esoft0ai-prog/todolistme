Webhooks reference

Camplo has three ways in and one way out. Inbound webhooks bring leads and their follow-up history into Camplo. Outbound webhooks tell your systems the moment something happens.

How it fits together

DirectionEndpointUse it forWhere you get it
InboundPOST /api/v1/hooks/{id}New leads from forms, funnels, cold-outreach replies, Zapier/Make, or your own codeSettings → Integrations → a lead source → Connect, or Settings → Webhooks & API → Inbound webhooks
InboundPOST /api/v1/lifecycle/{integrationId}/{token}What happened next: CRM stage changes, email enrolments, bookings, winsSettings → Integrations → a CRM or email tool
InboundPOST /api/v1/ingest/{workspaceId}/{pageId}Form submissions on pages Camplo hosts — wired automaticallyNothing to do
OutboundYour URLReact to lead.received, lead.responded, lead.assigned, sla.breached, campaign.completed, deployment.readySettings → Webhooks & API → Outbound webhooks

All URLs are on your Camplo domain, for example https://app.camplo.io/api/v1/hooks/…. Every request and response body is JSON (form-encoded bodies are also accepted inbound).

Lead webhook (inbound)

Each lead source gets its own URL, tied to one campaign (or to the Lead Inbox only). Camplo shows it on the integration card under Webhook URLs & settings:

POST https://app.camplo.io/api/v1/hooks/3f1c…e9a2?token=8d0b…71c4
Content-Type: application/json

The token query parameter is the workspace's secret for that webhook. Tools that can sign requests (Tally, Typeform, your own code) should sign instead — see Verifying requests. Treat the full URL like a password.

Lead payload

Send whatever your tool sends — Camplo recognises common field names, case-sensitive, at the top level or nested under data, contact or payload. Tally's data.fields[] and label-based fields are read automatically.

Camplo fieldAccepted keys (first match wins)
Namefull_name, fullName, name, your_name, or first_name/firstName/firstname + last_name/lastName/lastname
Emailemail, email_address, your_email
Phonephone, phone_number, phoneNumber, mobile
Source ID (deduplication / CRM matching)source_identifier, submission_id, submissionId, responseId, contact_id, id, eventId
UTMs (Growth and up)utm_source, utm_medium, utm_campaign, utm_content, utm_term
Source labelsource_system, source (defaults to the integration name)

A lead with no name is stored under its email, or "Unnamed lead". Minimal example:

{
  "name": "Ada Obi",
  "email": "ada@example.com",
  "phone": "+2348012345678",
  "submission_id": "sub_81723",
  "utm_source": "facebook",
  "utm_campaign": "black-friday"
}

Verifying requests

Camplo accepts a request when any one of these checks passes, using the webhook's signing secret:

MethodHeader / parameterValueUsed by
Camplo signatureX-Camplo-Signaturesha256= + hex HMAC-SHA256 of the raw body (prefix optional)Custom code
Tally signatureTally-Signaturebase64 HMAC-SHA256 of the raw bodyTally
Typeform signatureTypeform-Signaturesha256= + base64 HMAC-SHA256 of the raw bodyTypeform
Secret token?token= or X-Camplo-TokenThe signing secret itselfTools that can't sign: Systeme.io, GoHighLevel, Instantly, Apollo, Lemlist, Smartlead, Zapier, Make

Signing in your own code

# curl
BODY='{"name":"Ada Obi","email":"ada@example.com"}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$CAMPLO_SECRET" -hex | sed 's/^.* //')
curl -X POST "https://app.camplo.io/api/v1/hooks/$HOOK_ID" \
  -H "Content-Type: application/json" -H "X-Camplo-Signature: sha256=$SIG" --data "$BODY"
// Node.js
import { createHmac } from 'node:crypto';
const body = JSON.stringify({ name: 'Ada Obi', email: 'ada@example.com' });
const sig = createHmac('sha256', process.env.CAMPLO_SECRET).update(body).digest('hex');
await fetch(`https://app.camplo.io/api/v1/hooks/${hookId}`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-Camplo-Signature': `sha256=${sig}` },
  body,
});
# Python
import hmac, hashlib, json, os, requests
body = json.dumps({"name": "Ada Obi", "email": "ada@example.com"})
sig = hmac.new(os.environ["CAMPLO_SECRET"].encode(), body.encode(), hashlib.sha256).hexdigest()
requests.post(f"https://app.camplo.io/api/v1/hooks/{hook_id}", data=body,
              headers={"Content-Type": "application/json", "X-Camplo-Signature": f"sha256={sig}"})
Sign the exact bytes you send. Re-serialising JSON after signing (different spacing or key order) breaks the signature.

Lifecycle webhook (inbound)

CRMs and email tools post here when something happens to a lead after it arrives. Camplo matches the event to a lead by the external contact ID it has seen before, otherwise by email (most recent lead with that email), and remembers the ID mapping for next time.

POST https://app.camplo.io/api/v1/lifecycle/{integrationId}/{token}
Content-Type: application/json

{
  "event": "Appointment booked",
  "contact_id": "ghl_8812",
  "email": "ada@example.com",
  "occurred_at": "2026-10-02T09:14:00Z"
}
FieldAccepted keys
Event (required)event, stage, type, statusFree text. Events containing won, closed, booked or appointment are marked as milestones.
External contact IDcontact_id, person_id, external_contact_id, idRecommended
EmailemailFallback match
Whenoccurred_at, timestampISO 8601; defaults to now

The secret is part of the path, so no signature is needed. Lifecycle events power cross-tool SLA checks (Watchtower) and appear on the lead's timeline.

Hosted page forms

Pages uploaded to Camplo post their forms to /api/v1/ingest/{workspaceId}/{pageId}, signed with the page's own secret. Pausing a page hides it from visitors; its form endpoint keeps accepting submissions so nothing sent from an open tab is lost. Camplo injects the form handler for you — you only need it if you build a custom form handler, in which case use the page's webhook secret (page drawer → Webhook) with X-Camplo-Signature exactly as above. The payload format is the same as the lead webhook.

Responses & errors

StatusBodyMeaning
201{"ok":true,"lead_id":"…"}Lead created (lifecycle: event recorded)
202{"ok":true}Lifecycle only: accepted, but no matching lead yet
401{"ok":false}Signature or token didn't match
404{"ok":false}Unknown webhook, the integration was disconnected, or the hosted page was deleted
410{"ok":false}Hosted page forms only: the workspace has been suspended for more than 7 days
422{"ok":false}Lifecycle only: no event field

Bodies up to 1 MB are accepted. Retrying a 5xx is safe; include a source ID so you can spot duplicates.

Outbound webhooks: setting up

Settings → Webhooks & API → Add outbound webhook. Choose one event per webhook, enter an HTTPS URL, and (recommended) a secret. Add several webhooks to the same URL to receive several events.

Request format

POST https://your-server.example.com/camplo
Content-Type: application/json
X-Camplo-Event: lead.received
X-Camplo-Signature: sha256=5f2b…   (only when you set a secret)

{
  "event": "lead.received",
  "occurred_at": "2026-10-02T09:12:44.512Z",
  "data": { … event-specific fields … }
}

Events

lead.received — a new lead arrived

Fires for every lead from any source: hosted pages, lead webhooks, integrations.

"data": { "lead_id": "6b0e…", "name": "Ada Obi", "email": "ada@example.com", "campaign_id": "a91c…" }

email and campaign_id may be null.

lead.responded — someone responded to a lead

Fires when a teammate marks a lead responded (app, email link or Telegram). The SLA clock stops here.

"data": { "lead_id": "6b0e…", "name": "Ada Obi", "responded_by": "Tunde Bakare", "responded_at": "2026-10-02T09:19:02.000Z", "waited_ms": 378000 }

lead.assigned — the owner assigned a lead

"data": { "lead_id": "6b0e…", "assignee": "Tunde Bakare", "path": "B" }

path is "B" for a first assignment and "C" when a claimed lead is reassigned.

sla.breached — a lead passed its response threshold

Fires once per lead, when it passes the SLA (or VIP SLA) threshold without a response.

"data": { "lead_id": "6b0e…", "name": "Ada Obi", "waited_minutes": 31 }

campaign.completed — a campaign was marked complete

"data": { "campaign_id": "a91c…", "name": "Black Friday 2026" }

deployment.ready — a hosted page went live

Fires after an upload or redeploy finishes and the page is serving.

"data": { "deployment_id": "d77e…", "name": "bf-vip-early", "url": "https://pages.camplo.io/bf-vip-early" }

Verifying that a request came from Camplo

Compute HMAC-SHA256 of the raw request body with your secret and compare it (in constant time) with the hex after sha256=.

// Node.js / Express
import { createHmac, timingSafeEqual } from 'node:crypto';
app.post('/camplo', express.raw({ type: 'application/json' }), (req, res) => {
  const expected = createHmac('sha256', process.env.CAMPLO_SECRET).update(req.body).digest('hex');
  const got = String(req.header('X-Camplo-Signature') || '').replace(/^sha256=/, '');
  if (got.length !== expected.length || !timingSafeEqual(Buffer.from(got), Buffer.from(expected))) return res.sendStatus(401);
  const { event, data } = JSON.parse(req.body.toString('utf8'));
  // … handle event …
  res.sendStatus(200);
});
# Python / Flask
import hmac, hashlib, os
from flask import request, abort
@app.post("/camplo")
def camplo():
    expected = hmac.new(os.environ["CAMPLO_SECRET"].encode(), request.get_data(), hashlib.sha256).hexdigest()
    got = request.headers.get("X-Camplo-Signature", "").removeprefix("sha256=")
    if not hmac.compare_digest(got, expected): abort(401)
    payload = request.get_json()
    return "", 200

Delivery rules

  • Camplo waits up to 8 seconds for your server. Respond with any 2xx quickly and do slow work afterwards.
  • Delivery is attempted once. A timeout or non-2xx response is recorded as a delivery failure (monitored by Camplo) and the webhook's "last sent" time isn't updated.
  • Events can arrive out of order; use occurred_at to order them, and lead_id to make handling idempotent.
  • Disable or delete a webhook any time in Settings → Webhooks & API.
Need a field that isn't listed? Send it anyway — Camplo stores what it recognises and ignores the rest.
